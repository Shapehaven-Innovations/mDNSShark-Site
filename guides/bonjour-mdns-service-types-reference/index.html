Bonjour / mDNS service types reference

Last checked October 9, 2026

A Bonjour service type is a name like _ipp._tcp: a service name, then the transport protocol. Devices advertise these over mDNS (RFC 6763) so other devices can find them. Below are common types, with ports from the IANA service-name registry.

Common service types

Service typeWhat it isTypical devicesDefault portSource
_http._tcpWorld Wide Web HTTP. Used to advertise a web page or web interface.Routers, NAS boxes, printers (admin pages), IoT gadgets80IANA: http
_ssh._tcpThe Secure Shell (SSH) protocol.Macs and Linux machines with remote login on, Raspberry Pi, NAS boxes22IANA: ssh
_ftp._tcpFile Transfer Protocol (control connection).NAS boxes, older network storage21IANA: ftp
_ipp._tcpInternet Printing Protocol.Network printers, print servers631IANA: ipp
_ipps._tcpInternet Printing Protocol over HTTPS.Network printers, print servers631IANA: ipps
_printer._tcpLine printer spooler (LPD).Network printers, print servers515IANA: printer
_pdl-datastream._tcpPrinter PDL data stream (raw printing).Network printers9100IANA: pdl-datastream
_afpovertcp._tcpApple Filing Protocol (AFP) over TCP.Macs with file sharing, NAS boxes, Time Capsule-style storage548IANA: afpovertcp
_nfs._tcpNetwork File System.Linux and Unix servers, NAS boxes2049IANA: nfs
_daap._tcpDigital Audio Access Protocol, used for iTunes library sharing.Computers sharing a music library3689IANA: daap
_rfb._tcpRemote Framebuffer, the protocol behind VNC screen sharing.Macs with screen sharing, Linux desktops5900IANA: rfb
_airplay._tcpProtocol for streaming audio and video content.Apple TV, AirPlay-capable TVs and speakersnot definedIANA: airplay
_homekit._tcpProtocol for home hub communication.Home hubs and HomeKit accessoriesnot definedIANA: homekit
_googlecast._tcpService related to Google Cast, a technology for multi-screen experiences.Chromecast devices, Cast-enabled TVs and speakersnot definedIANA: googlecast

"Not defined" means the IANA registry lists the service name but assigns no port number. For those types the port comes from each device's SRV record, so read it from a resolve rather than assuming one. Where a registry entry has a port, a device can still advertise a different one in its SRV record.

How to browse these with mDNSShark

On an iPhone, run a scan in mDNSShark and look for these service types among the results. mDNSShark discovers services over Bonjour/mDNS (DNS-SD) and SSDP, so a printer shows up under its printing types and a Mac with remote login on shows up as _ssh._tcp. To list every type on the network from a Mac or Linux machine instead, see How to list every Bonjour (mDNS) service on your network. Once you know a type, you can browse it directly, for example dns-sd -B _ipp._tcp local.

Only scan networks you own or have permission to examine.

How this list was compiled

Service names, descriptions and ports come from the IANA Service Name and Transport Protocol Port Number Registry. The service-type format (_name._tcp) comes from RFC 6763. Each row links to its registry entry.

A row is included only if the registry lists that name with the tcp transport. Names the registry lists without any transport or port (smb, raop and adisk, for example) are left out because the registry does not confirm them as _tcp types. The "What it is" column paraphrases the registry description. The "Typical devices" column is general context and is not registry data. Registry entries change over time, so check the linked entry if a detail matters. This table was last checked against the registry on October 9, 2026.
